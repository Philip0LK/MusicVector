# 乐北斗 · 手机练习端（安卓）

电脑端把**已经标定好**的曲目通过二维码发到手机，手机横屏逐音练习。
手机端**只有接收和播放**：没有识别、没有校对、没有改谱、没有歌曲管理以外的编辑能力。

## 怎么用

1. 电脑端打开这首曲子，点训练区顶栏**拍号旁边**的「发送到手机」。
2. 电脑上出现二维码（约 10 分钟有效）。
3. 手机上打开本 App → 「扫描二维码接收曲目」→ 对准二维码。
4. 接收完成后自动进入练习页；之后**断网也能练**（数据已存在手机上）。

因为原谱图片约 1.6 MB，二维码只能承载地址，所以：

- 手机和电脑必须在**同一个 Wi‑Fi**；
- 电脑端只要跑 `npm run dev` 就行——这一条命令会同时起界面、「发送到手机」服务和局域网监听，检测到插着 USB 调试的手机时还会顺手做 adb reverse 并拉起本 App。启动后终端会打印手机该用的地址。
- 电脑端面板会直接提示这一点。

如果连不上，按这个顺序排查：

- **不要用 ping 判断通不通**：校园网、酒店网络常常只挡 ICMP——`ping` 100% 丢包，但 HTTP 本身是通的。
  实测过这种情况：同一校园网下 ping 电脑完全不通，手机扫码接收却完全正常。以 App 里的提示为准。
- 确认电脑端是用 `npm run dev` 起的，且面板上显示的地址与手机在同一网段（用 `npm run dev:local` 起的话只监听本机，面板会直接提示）。
- 电脑上的 Windows 防火墙要允许 Node 入站（首次启动通常会弹窗，选「允许」）。
- 确实遇到客户端隔离（同一 Wi‑Fi 下两台设备互相访问不了）时，用一台设备开热点、另一台连上去即可。

## 界面与操作

横屏。顶部是曲名、`1=E4`（基准音区）、拍号，右上是设置；中间是**上面一行原谱图片、下面一行简谱**的整首连续滚动；底部是播放栏。

原谱条带按屏宽铺满：高度由裁切图自身的宽高比算出来（不固定），这样图和谱共用同一条左右边界。
早先条带固定 44dp 高、图片按高度装进去，实际只占屏宽的一半左右并居中，和铺满整行的简谱对不齐。
代价是原图分辨率低的页面会被放大得更多（放大走 Android 的双线性插值）：原图 1440px 宽的页面放大
约 1.6 倍基本无损，710px 宽的页面要放大 3.3 倍、明显发虚——这类页面重新用更高分辨率导入即可。

与电脑端逐条对齐的播放行为：

| 电脑端 | 手机端 |
| --- | --- |
| 空格播放/暂停 | 「播放/暂停」按钮 |
| Enter 试听当前音 | 「试听当前音」 |
| 当前音未播放过时，←→ 第一次只试听当前音，第二次才换音 | 「上一音/下一音」同规则 |
| 从头播放（有选段时从片段头） | 「从头播放」 |
| 选段 + 片段自动循环（每轮间隔 1 秒）+ 取消选段 | 「选段」+ 谱面点选起止音 |
| 倍速 0.5/0.75/0.9/1/1.1，0.05 步进，0.25–1.25 | 「速度」弹层，同一组数值 |
| 播放中调速从当前音重新调度 | 同 |
| 自动跟随滚动，手动滚动后停止跟随 + 「回到当前音」 | 同（手指滚动即停止跟随） |
| 休止符只推进时间轴、同音延音合并成一次发声 | 同（延音关系由电脑端算好） |
| 播放前预载采样，个别采样失败只让该音高降级 | 播放前解码本曲要用的采样，缺某个音高只让它静音 |
| 速度/位置持久化 | 同（按曲目存本机） |

设置里可以改**基准音区**（`1=E4`，会整首移调）和**BPM**（1× 对应的原速）。这两项只影响手机上这一首的练习，不会回写电脑端。

### 发声规则（与电脑端同源）

产品要的是**精确的时值比例**：八分正好是十六分的两倍，附点正好一点五倍。所以每个音的可听窗口
**正好等于它自己的时值**，淡入淡出按时值比例缩放（淡入 ≤ 时值 20%、收尾 ≤ 30%），比例不会被淡出破坏，
也不会出现硬切的爆音。电脑端（`src/lib/envelope.js`）与手机端（`PcmMixer.kt`）是同一份规则的两份实现，
两侧各有测试钉住：`tests/envelope.test.mjs` 与 `SoundLengthTest.kt`。

早先两边都是「时值 + 固定 35ms 收尾」，那个固定尾巴会把比例压成 1.87（455+35 : 227+35）而不是 2；
现在两边都已改成比例精确。

**试听当前音是例外**：试听不按谱面时值切，直接让采样自然响完（低音会响到十几二十秒），
这样才听得清一个音；按需解码整段采样，只影响被点到的那一两个音高。

### 其它差异

- 没有键盘快捷键（手机没有键盘），↑↓ 切行由点击/滚动代替。
- 只带 medium 一档钢琴采样。


## 构建

工具链（JDK 17 + Android SDK + Gradle 8.10.2）不放进仓库。脚本按顺序找
`YUEBEIDOU_TOOLING` 环境变量 → 工程内 `.tooling` 目录联接。首次使用：

```powershell
# 指向本机已装好的工具链（或设 YUEBEIDOU_TOOLING 环境变量）
New-Item -ItemType Junction -Path .\.tooling -Target E:\AI\知音音韵\zhiyin\.tooling

# 单测
.\scripts\gradle-local.ps1 :app:testDebugUnitTest

# 出包（加 -Install 会 adb install -r）
.\scripts\build-apk.ps1
.\scripts\build-apk.ps1 -Install

# 装机后自动装、拉起、截图并收集 logcat（截图与崩溃记录写到 qa/）
.\scripts\verify-device.ps1
```

工程路径含中文，AGP 不接受，所以脚本会先用 `subst` 映射一个盘符再构建。

## 测试

`app/src/test/.../DesktopParityTest.kt` 是「与电脑端一致」的核心保证：期望值来自电脑端仓库根目录的
`tools/mobile-fixtures.mjs`，覆盖播放计划（延音合并、附点、休止、区间、倍速、
多个 BPM）、音高偏移与换基准音区、小节排版字形、裁切矩形。

`SoundLengthTest.kt` 盯住发声：可听窗口正好等于时值，各时值之间正好成整倍数（16:8:4:2:全 = 1:2:4:8:16，
附点正好 1.5 倍），容差只留一个采样帧的取整误差。任何「固定的额外时长」或「被固定扣掉的时长」都会让它失败——
用户实测到的"十六分比两倍还快"就是后者。

发声音质的一次定型（2026-09-18）：原先用 `SoundPool`，按计划时刻去 `stop`，而 SoundPool 起声有设备输出延迟，
每个音都被扣掉同一个延迟量，于是短音损失比例更大、16 分被听成"比两倍还快"。现在改成自己解码 PCM +
`AudioTrack` 流式混音，起声与收尾都落在采样帧上，实测 `AudioTrack.underrunCount = 0`。

电脑端改了播放或排版算法后，必须重新生成 fixture，否则 Node 侧 `tests/handoff.test.mjs`
与安卓侧 `DesktopParityTest` 都会失败：

```powershell
cd ..
npm run fixtures:mobile
```

## 装机验证（电脑旁没有可用 Wi-Fi 时）

USB 调试连接后可以完全绕开网络做验证——`adb reverse` 把手机的 `127.0.0.1:4177` 转发到电脑的 4177，
再用深链把曲目地址直接交给 App，就不需要相机扫码：

```powershell
adb reverse tcp:4177 tcp:4177
# 电脑端打开一首曲子，点「发送到手机」，从面板上复制地址（手机端口即 4177）
adb shell am start -a android.intent.action.VIEW -d "yuebeidou://receive?u=<urlencoded 地址>"
# 截图、按文字精确点击、查崩溃
.\scripts\verify-device.ps1
node scripts\ui-bounds.mjs qa\ui.xml
```

真机实测记录（Redmi 23013RK75C / Android 15 / 横屏 914×411dp）：

- **相机扫码 → 接收**：使用者在校园网下自行扫码导入了一首电脑端曲库里的《太阳与地球》（178 音 / 6 行 / 2 页），
  手机上的 manifest 生成时间与电脑端点击「发送到手机」的时刻一致，四页图片齐全。
  同一网络下 `ping` 电脑 100% 丢包，但 HTTP 正常——排查时不要用 ping 下结论。
- 接收（含电脑端真实地址）、练习页「图在上谱在下」整首滚动、播放/暂停/自动跟随，
  上一音下一音（首次点击不跳音）、试听当前音、选段循环（15 秒内 12 帧有 11 帧不同，证明确实在反复重播）、
  倍速（0.5× 显示 40 拍/分钟）、设置改调号与基准音区且重启后保持、二维码过期与连不上电脑时的提示与出口，
  均已通过。
