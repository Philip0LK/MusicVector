# 符号算法基线：首轮实验

日期：2026-09-12。当前切片算法保持不变。本次未调用 AI，也未修改产品识别链路。

## 可复现

```powershell
python scripts/prepare-symbol-baseline.py
node scripts/evaluate-symbol-baseline.mjs
```

标签及源图哈希：`output/symbol-baseline/labels.json`。
逐音错误和汇总：`output/symbol-baseline/results.json`。
标注依据图：`output/lyric-slices/baseline-source.jpg`。

5 个真实切片、78 个音符，来自富士山下、K歌之王、BabySong，包含单双减时线、附点、低音点、歌词、延时横线和短末行。标签在执行算法之前人工从图片阅读建立，没有按运行结果反向修改，也没有调参。样本为有意选择的试探样本，非随机、非独立大规模基准，仅由一人查看，仍需复核。

## 被测对象与条件

运行原版 `src/octaveDetector.js` 的 `analyzeRhythmSymbols` 和 `analyzeLowOctaves`。与浏览器适配器一样，将输入缩放至 1440 像素宽。本次测试用当前行切片作为输入，并给定人工音符数字序列；不是对旧版整页完整链路的复现。

算法使用音符数量及顺序匹配几何，因而这是“正确音符序列条件下的附属符号识别”，不是独立音符识别。小节结束真值也按音符索引记录。不能据此推断数字识别、AI 识别或实际产品端到端准确率。

## 原始切片结果

| 项目 | 结果 | 解释 |
|---|---|---|
| 减时线数量 | 76/78，97.4% | 每音符 0/1/2 条的精确分类 |
| 附点 | 真阳性3、假阳性2、漏检0 | 精确率60%，召回100%；正例很少 |
| 小节结束 | 真阳性7、假阳性0、漏检6 | 精确率100%，召回53.8% |
| 低音点 | 真阳性2、假阳性0、漏检0 | 只有2个正例，不足以宣称可靠 |

变体测试（不是额外独立样本）：
- 先缩小到75%再走输入流程：减时线77/78；附点正确找到1个、误报1个、漏掉2个。
- 亮度提高10%：减时线75/78；附点正确找到3个、误报1个。
- 两类扰动中，小节结束均只找到7/13；低音点仍为2/2。

具体失败：短末行中的歌词“咒。”被误用为音符几何，产生假的减时线和附点；BabySong 的一行漏掉全部5个小节结束，且存在一次附点误报与一次减时线数量错误。定位/匹配失败会同时污染多个属性，不能只给各属性单独打高置信度。

## 接入边界建议

- 保留当前裁切版本；首版不做异常自动重识别，只记录校验错误交给修正界面。
- 不再坚持每行一个请求：识别数据仍以行为单位，调用层试用同页连续2～4行的独立图片批次，建议起点3行。8张素材共66行，从66次可降到24次（不含头部识别）。这是配置起点，尚未验证AI质量或实际费用。
- 成本分开记录重复提示词、图像输入、结构化输出、可选思考token；多图放同请求不能保证图像token同步减少。记录真实usage后再比较1/3/整页策略。
- 算法当前只输出候选及证据，不直接覆盖AI。减时线可优先作为混合识别试验项目；附点、小节线暂不能算法独占；低音点先扩大正例样本。
- 音符数字、变音记号、高音点、弧线、连音组、反复结构、歌词尚未在本次得到测量结论。
- 下一轮需要同一批人工真值上的AI/算法/混合三组对照。不要把旧数据中的未经核对识别结果作为真值。
