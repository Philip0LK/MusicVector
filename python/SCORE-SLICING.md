# 整行简谱＋歌词切片实验

## 运行

在项目根目录运行（Python，需要 numpy、opencv-python、Pillow）：

```powershell
python scripts/score_slicer.py img_data --check-stability
python scripts/build_slice_review.py
```

查看 `output/lyric-slices/index.html`；每张图的 `result.json` 保存坐标、几何证据和警告，`row-N.png` 是原图像素裁切。没有 AI、OCR、模型调用，也没有按歌曲名写入的坐标。没有改写训练 Demo 或人工校对数据。

## 方法与参考

1. EXIF 方向归一化，检测图统一宽度 1400，保留原图作最终裁切。
2. 暗色核心二值化，减轻浅色水印干扰。
3. 形态学提取长横线和竖线，识别伴奏谱表区域。
4. 连通域的尺寸、宽高比、密度、基线和间距联合提出简谱行候选；结合小节线与伴奏相对位置过滤和弦图、页眉数字。
5. 在旋律下方寻找连续文字带，支持双行歌词；向上保留附近反复房子横括号。
6. 将检测坐标映射到方向归一化的原图，输出 V2 `image-normalized` 坐标。

参考依据：
- OpenCV 官方形态学谱线提取示例：https://docs.opencv.org/3.0.0/d1/dee/tutorial_moprh_lines_detection.html
- MUSER 原论文，形态学、连通域和结构推理：https://haralick.org/journals/muser.pdf
- 简谱识别论文中的投影分割方法：https://www.mdpi.com/2075-1702/13/12/1121

这些资料提供基础方法，并没有证明其对本项目的水印、伴奏混排素材能达到某个准确率。本文实现也不采用固定每行小节数或均分切片的方法。

## 当前评估

8 张原始素材检测共 66 行：BabySong 两页各 5；K歌之王 15；Shall We Talk 15；富士山下两页 9、8；爱是怀疑两页 4、5。原始素材行数与人工查看一致，但这不是像素边界准确率或独立测试集准确率。

扰动测试：
- 缩小到 75%：BabySong 第 2 页从 5 行变成 4 行；K歌之王从 15 行变成 16 行。
- 亮度提高 10%：Shall We Talk 从 15 行变成 16 行；富士山下第 1 页从 9 行变成 11 行。
- 其余这些扰动测试行数不变；行数不变仍不能证明边界无偏差。

`--check-stability` 将行数分歧记录为 `unstable-row-detection`。无歌词的行记为 `no-lyrics-detected`，可能只是器乐行。所有输出均 `reviewed: false`、`reviewRequired: true`，不覆盖任何既有正确切片。源图与字体的几何阈值仍存在敏感性，当前是实验版本，不应无审核上线。

## 坐标契约与限制

- 矩形基准：EXIF 方向归一化后原图；左上为原点，x/y/width/height 为 0～1。读取方必须使用相同方向和原图尺寸。
- 当前横向保留整页宽度，避免裁掉短行、左右端符号；不会擦除切片中的水印和侧边装饰。
- 分析用的去线掩码不会修改导出的原始图片内容。
- 当前未提供倾斜/透视矫正、多栏排版或跨行歌词语义判定。深色水印和笔画叠加无法仅凭这一算法可靠还原。
- 下一轮优先把候选行的单一硬阈值改成多阈值一致性和整页序列评分，并补充独立素材标注基准；需要同时评估完整音符符号覆盖率、歌词完整率及伴奏混入率，不能只比较行数。
